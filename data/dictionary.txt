================================================================================
GOALDATA LEAGUE - DATA DICTIONARY
================================================================================
This is the authoritative data dictionary for the processed datasets in
data/processed/. It replaces the earlier free-text generation prompt.

For every column we state: meaning, type, unit, and PROVENANCE. Provenance is the
single most important field for the defense, so each value is labelled as one of:

  - observed   : taken directly from a real source (e.g. real final scores,
                 real player profiles, real FBref season totals).
  - derived    : computed deterministically from observed values
                 (e.g. per-90 rates, goal_difference, BMI, win flags).
  - simulated  : produced by a documented statistical model anchored on observed
                 quantities, because the granular real value is not available.
                 Simulation is NEVER arbitrary; see "Simulation methodology".

A machine-readable provenance tag also exists as the column `data_provenance`
in each processed table.

--------------------------------------------------------------------------------
SIMULATION METHODOLOGY (why simulated values are defensible)
--------------------------------------------------------------------------------
The heavy granular tables (per-match player stats, goal events) are not available
as real data for the full 2004-2026 / 94k-match scope. Where we must simulate, we
anchor on REAL quantities and documented models instead of random buckets:

1. Goals per player-match are allocated from the REAL match scoreline. Each team's
   real goals (home_score / away_score) are distributed across that team's players
   with a multinomial whose weights are position scoring-propensity x minutes. By
   construction, the sum of player goals equals the real team score for every match.
     Refs: Maher (1982); Dixon & Coles (1997) [Poisson scoring];
            Decroos et al. (2019) [per-90 / action valuation].
2. Shots follow from goals via position conversion rates (a scorer needs shots),
   preserving shots >= goals and shots = on_target + off_target + blocked.
     Refs: Pollard & Reep (1997) [shot effectiveness].
3. goals_events_cleaned is rebuilt as the REAL-sized goal table (~254,596 rows =
   the real number of goals). Minute uses a documented increasing-hazard profile,
   goal_type uses real base rates (~8.5% penalties, ~2.2% own goals), assists use
   position creation-propensity (~74% of non-penalty goals assisted).
4. Missing real fields are imputed only with statistically related observed data
   (grouped medians / per-90 priors), never with unconditioned constants.
     Refs: Little & Rubin (2002); van Buuren (2018).

Full citation list at the bottom of this file and in reports/methodology_and_citations.md.

--------------------------------------------------------------------------------
ENTITY RESOLUTION (consistent identities and characters)
--------------------------------------------------------------------------------
All player names are normalised to one character convention (Unicode NFKD ASCII
fold, lower-case, separators unified, camelCase split). Surface variants such as
"Cristiano Ronaldo" / "cristiano_ronaldo" / "CristianoRonaldo" / "CR7" /
"C. Ronaldo" collapse to a single canonical player_id via deterministic
normalisation + a nickname map + rapidfuzz token-sort fuzzy merge
(src/entity_resolution.py). player_id / assist_player_id are the canonical ids.

exactly like the players table is allowed to be "small" by logic.

================================================================================
RELATIONSHIPS / JOIN KEYS
================================================================================
players.player_id      -> player_match_stats / player_season_stats / goalkeeper_stats / goals_events
teams.team_id          -> players / matches (home/away) / player_match_stats
matches.match_id       -> player_match_stats / goals_events
goals_events.player_id -> players ; goals_events.match_id -> matches
